# 平台管理员入口与企业管理员密码重置设计

## 目标

在普通公司用户登录页 `/login` 增加平台管理员入口，并在现有平台控制台中提供企业管理员密码重置能力。该功能同时适用于本地开发和生产部署，继续保持平台身份与企业身份严格分离。

## 普通登录页入口

- 保留公司用户登录表单和主按钮不变。
- 在“登录”按钮下方增加轻量分隔区域。
- 显示“平台管理员入口”文字链接，并附带“用于公司开通、域名与企业管理员管理”的简短说明。
- 点击后通过 React Router 跳转到 `/platform/login`，不刷新整页。
- 入口不携带、不转换也不清理公司用户令牌；平台登录继续使用独立的 `platform_token`。
- 本地和生产使用相同代码，不设置环境开关。

## 企业管理员展示与密码重置

- 在平台控制台的“公司详情”抽屉中新增“企业管理员”区域。
- 只展示目标公司内角色为 `admin` 的账号，包括姓名、邮箱和启用状态。
- 每个企业管理员提供“重置密码”操作；平台管理员不能通过此入口修改 HR、面试官或其他角色的密码。
- 重置弹窗要求输入新密码和确认密码，不显示、读取或返回原密码。
- 新密码必须为 12–72 个 UTF-8 字节，并且至少包含一个字母和一个数字；前后端使用一致规则。
- 重置成功后关闭弹窗、显示成功反馈，并更新该账号的凭据版本。

## API 与数据结构

- 公司详情响应增加 `admins` 数组，避免前端再发起一条可产生竞态的独立读取请求。
- 新增平台接口 `PATCH /api/platform/tenants/{tenant_id}/admins/{user_id}/password`。
- 请求体只接受 `new_password`，拒绝额外字段；响应只返回成功状态，不返回密码或密码散列。
- `users` 表新增整数型 `credential_version`，默认值为 `1` 且不可为空。
- 企业登录令牌加入 `credential_version` 声明；每次认证在读取当前用户后比较令牌版本和数据库版本。
- 修改密码时在同一事务中写入新密码散列并递增 `credential_version`，从而立即使该账号此前签发的所有令牌失效。
- 用户自行修改密码时也使用同一版本递增机制，保持一致的安全行为。

## 租户隔离与授权

- 密码重置接口只接受有效的独立平台令牌，不接受企业令牌。
- 服务层先验证平台操作者仍存在且处于启用状态，再确认目标公司存在。
- 访问企业用户数据前显式绑定目标公司的租户上下文，并同时按 `tenant_id`、`user_id` 和 `admin` 角色筛选目标账号。
- 找不到公司或找不到符合条件的企业管理员时返回统一、无敏感信息的错误。
- 事务结束后释放平台跨租户操作使用的上下文，避免后续请求继承错误租户。

## 审计与错误处理

- 重置成功后写入 `platform_audit_logs`，操作名为 `tenant.admin_password_reset`。
- 审计内容只记录目标管理员 ID、规范化邮箱和新的凭据版本，不记录明文密码、确认密码或密码散列。
- 密码校验失败返回安全的 422 响应；目标不存在返回 404；平台操作者无效返回 403；内部异常返回通用错误。
- 密码更新和审计写入处于同一事务，任何一步失败都整体回滚。

## 测试与验收

- 登录页能显示平台管理员入口及用途说明，点击后路由切换到 `/platform/login`。
- 公司详情能展示企业管理员，但不展示 HR 和面试官。
- 有效平台令牌可以重置指定公司的企业管理员密码，新密码可登录，旧密码不可登录。
- 重置后旧企业令牌立即失效，新登录签发的令牌可正常访问。
- 不能跨公司命中同 ID 或邮箱的其他账号，不能修改非 `admin` 角色账号。
- 弱密码、超长 UTF-8 密码、额外请求字段和无效目标均被拒绝，且日志与响应不泄露密码。
- 审计记录包含正确的操作者、公司和目标管理员信息。
- 数据库迁移可升级并可回滚；后端测试、前端测试和生产构建全部通过。
- 本地 Docker 更新后，`/login` 与 `/platform/login` 均返回 HTTP 200，实际界面可完成密码重置流程。
