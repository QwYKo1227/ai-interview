# 笔记本小屏响应式布局设计

## 背景

当前管理端在笔记本常见视口（1280×720、1366×768，尤其叠加系统缩放时）存在两类横向溢出：

- 岗位列表宽度超过内容容器，右侧操作按钮被挤出可视区域。
- 简历详情右栏头部在同一行放置候选人信息、匹配度、状态和全部操作按钮，内容宽度超过右栏。

简历详情需要继续保持左右双栏，以便用户同时对照简历原件和 AI 分析结果。

## 目标与验收标准

- 在 1280×720、1366×768 和常规大屏视口下，页面外层不产生横向滚动。
- 笔记本宽度下左侧导航自动折叠为图标栏。
- 折叠菜单的每个图标在鼠标悬停或键盘聚焦时显示完整菜单文字。
- 岗位表格过宽时仅在表格容器内部横向滚动，右侧操作列保持可见。
- 简历详情始终保持左右双栏；标题、状态和操作按钮均在右栏范围内完整显示。
- 常规大屏继续使用当前展开侧栏和既有页面视觉结构。

## 设计方案

### 应用布局

应用布局监听 Ant Design 响应式断点。在笔记本宽度及以下，侧栏自动切换为折叠宽度；宽度恢复后自动展开。主内容区的左边距与侧栏实际宽度同步，避免保留展开态空白。

菜单项保留图标。折叠时使用可访问的 Tooltip 展示完整菜单名称，支持鼠标悬停和键盘聚焦；展开时不重复显示 Tooltip。

页面内容边距在笔记本断点下适度收紧，为业务内容释放空间，但不改变现有配色、字号体系和大屏视觉风格。

### 岗位列表

为表格定义明确的横向内容宽度，并启用表格容器自身的横向滚动。操作列设置固定宽度并固定在右侧，使查看、发布或下架、复制、编辑和删除操作在小屏下仍可直接使用。

列内容使用合理宽度和换行策略，避免浏览器无约束地压缩列。页面标题操作区和筛选区继续允许换行，保证新增岗位和批量操作不会撑出容器。

### 简历详情

左右预览结构保持不变。两个面板都设置 `min-width: 0`，允许 Flex 子项在可用空间内正确收缩，而不是由内部内容反向撑宽父容器。

右栏头部拆分为两层：第一层显示候选人信息、匹配度和流程状态；第二层独立承载操作按钮并允许换行。按钮顺序、权限和业务行为保持不变。

左侧预览头部在空间不足时允许标题与下载操作收缩或换行；文件预览区域继续占满左栏。左右栏继续各自处理已有的纵向滚动，不引入页面级横向滚动。

## 状态与数据流

响应式状态仅由当前视口断点派生，不写入后端，也不改变用户数据。视口跨越断点时，侧栏折叠状态、内容左边距和紧凑间距同步更新。

岗位列表和简历详情的请求、权限判断、按钮事件及业务状态不变。本次仅调整布局和表格展示约束。

## 边界与异常处理

- 超长用户名、候选人邮箱和岗位名称继续使用换行或省略提示，不允许撑破容器。
- 操作按钮数量随业务状态变化时，按钮区自动换行。
- 表格列总宽度超过容器时出现局部滚动条，不裁剪操作列。
- Tooltip 文本取自现有菜单标签，避免维护两份名称。
- 本次以笔记本和桌面管理端为范围，不重新设计移动端导航和简历详情。

## 验证方案

- 添加布局行为测试，验证笔记本断点下侧栏折叠、主内容偏移同步及菜单 Tooltip 可用。
- 添加页面结构测试，验证岗位表格启用横向滚动且操作列固定。
- 添加简历详情结构测试，验证左右双栏保留、面板可收缩、操作区可换行。
- 执行前端 lint 与生产构建。
- 在 1280×720、1366×768 和大屏尺寸进行浏览器截图检查，确认页面无横向溢出、按钮完整可见且大屏无回归。

## 非目标

- 不调整业务接口、权限逻辑或按钮功能。
- 不更换整体视觉主题。
- 不将简历详情改成上下布局。
- 不对所有业务页面进行全面移动端重构。
