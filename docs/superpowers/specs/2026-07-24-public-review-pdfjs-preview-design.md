# 部门评审页 PDF.js 预览修复设计

## 背景

部门评审页已经能够通过评审令牌安全获取简历 PDF，并在左侧创建原生 PDF `iframe`。实际部署验证显示：

- 评审接口返回 `file_available: true`；
- 文件接口返回 `200 application/pdf`；
- 页面中的 `iframe` 已挂载且指向有效的 Blob URL；
- 部分浏览器或 WebView 仍将原生 PDF 查看器渲染为空白。

因此问题位于浏览器原生 PDF 插件的兼容性，而不是文件、权限或布局。

## 目标

- 使用应用内 PDF.js 渲染替代原生 PDF `iframe`。
- 保持现有评审令牌文件接口、下载按钮、双栏布局和移动端堆叠布局。
- 提供明确的加载、渲染失败和分页状态。
- 不把简历文件或链接发送给第三方服务。

## 非目标

- 不修改简历上传格式或后端存储方式。
- 不改造简历管理、面试评分等其他页面的 PDF 预览。
- 不增加批注、搜索、打印或复杂缩略图功能。

## 方案

前端引入 `pdfjs-dist`，新增一个职责单一的 PDF 预览组件。组件接收现有受保护文件 Hook 生成的 Blob URL：

1. PDF.js 从 Blob URL 加载文档。
2. 组件将当前页渲染到 Canvas。
3. 根据预览容器宽度计算缩放比例，使页面适配可用宽度。
4. 用户可切换上一页、下一页，并查看“当前页 / 总页数”。
5. 容器尺寸变化时重新渲染当前页。
6. 文档 URL 变化或组件卸载时取消旧渲染任务并销毁 PDF 文档。

PDF.js Worker 使用随构建产物发布的模块 Worker URL，不依赖公共 CDN。

## 页面状态

- 文件请求中：显示加载指示。
- PDF 加载或页面渲染中：显示轻量加载状态，保留预览容器结构。
- PDF 渲染成功：显示 Canvas 和分页控件。
- PDF 加载或渲染失败：显示“简历预览加载失败，请下载原件查看”，下载按钮仍可用。
- 非 PDF：继续显示当前的“不支持在线预览，请下载原件”状态。
- 无原件：继续显示当前的“暂无简历原件”状态。

## 安全与数据流

数据流保持为：

`评审令牌 -> 同源文件接口 -> Blob -> PDF.js -> Canvas`

PDF 数据不进入第三方服务。已审批、过期、跨租户或资源不匹配时，仍由现有后端规则拒绝文件访问。

## 测试

- 组件测试验证 PDF 使用 Canvas 渲染，不再生成 `iframe`。
- 验证加载成功后显示页码与翻页控件。
- 验证渲染失败时显示下载兜底提示。
- 更新部门评审页测试，验证 PDF 预览组件接收文件 Blob URL。
- 运行前端相关测试、前端全量测试和生产构建。
- 重建本地 Docker 前端，并在实际评审链接验证：
  - 新资源版本已加载；
  - PDF Canvas 存在且尺寸非零；
  - 桌面端保持左右双栏；
  - 下载按钮仍可用。
