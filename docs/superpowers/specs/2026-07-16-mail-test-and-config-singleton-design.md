# 测试邮件与系统配置单例设计

## 目标

将邮件设置中的测试操作改为向管理员指定的收件人真实发送测试邮件；支持两种加密 SMTP 连接方式；并将数据库中的系统配置合并为唯一记录。

## 用户流程

1. 管理员保存 SMTP 设置。
2. 在“系统设置”中填写测试收件人邮箱，并选择加密连接方式：
   - **SMTP SSL**：默认方式，通常使用 465 端口。
   - **STARTTLS/TLS**：通常使用 587 端口。
3. 点击“发送测试邮件”后，前端调用邮件测试接口并提交收件人。
4. 后端校验收件人和 SMTP 配置，按选定方式建立连接、认证并发送测试邮件。
5. 只有 SMTP 服务端接受邮件后，页面才显示成功；否则显示不暴露密码的可操作错误提示。

## 后端设计

- 在系统配置和邮件设置接口中增加 `smtp_security` 字段，可选值为 `ssl` 与 `starttls`；存量配置默认使用 `ssl`。
- 邮件测试接口改为接收包含 `recipient` 的请求体。接口校验邮箱格式，调用邮件服务并在真实发送失败时返回错误。
- 邮件服务在 `ssl` 模式下使用 `SMTP_SSL`，在 `starttls` 模式下使用 `SMTP` 后调用 `starttls()`；继续复用现有邮件内容构造逻辑。
- 增加统一的系统配置读取器：保留最近更新的记录，用旧记录补全其缺失字段，并在同一事务中删除重复记录。
- 增加数据库迁移：清理已有重复配置、加入单例标记及唯一约束、初始化已有记录。之后所有系统设置读写均通过统一读取器完成。

## 前端设计

- 在 SMTP 端口旁增加“加密连接方式”选择框。
- 增加“测试收件人”邮箱输入框；该值仅用于当前测试请求，不保存为系统配置。
- 将“测试连接”改为“发送测试邮件”。成功提示明确表示 SMTP 服务端已接受该邮件。

## 错误处理与安全性

- SMTP 密码保持只写，不返回前端，也不写入日志。
- 收件人格式错误返回 HTTP 422；邮件配置缺失或未启用返回 HTTP 400；连接、TLS、认证和发送失败返回不含敏感信息的失败响应，并仅在服务端记录详细日志。
- 只有管理员可访问邮件设置和测试邮件接口。

## 验证方式

- 单元测试覆盖：收件人校验、SSL 模式、STARTTLS 模式、SMTP 认证失败、发送失败和发送成功。
- 路由测试覆盖：请求校验和响应状态。
- 迁移测试覆盖：重复记录合并、缺失字段补全，以及第二条单例配置被拒绝。
- 前端构建验证新增表单与请求类型。
