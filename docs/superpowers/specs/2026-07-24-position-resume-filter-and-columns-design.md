# 岗位与简历筛选及岗位列表字段调整设计

## 目标

统一岗位管理与简历管理的筛选样式和交互，并完善岗位列表展示字段与简历应聘岗位筛选，使用户能够通过一致的即时筛选体验快速定位岗位和候选人。

## 已确认范围

- 岗位管理与简历管理均使用卡片式横向筛选栏。
- 两个模块的筛选条件变更后立即生效，不需要点击“搜索”。
- 两个模块均不显示“搜索”按钮，只保留“重置”按钮。
- “重置”一次清空当前模块的全部筛选条件并恢复完整列表。
- 岗位列表删除职位类型列，新增招聘人数和招聘负责人列，并按指定顺序排列。
- 简历管理新增应聘岗位筛选。
- 不改变现有角色权限或数据可见范围。

## 岗位管理筛选

岗位筛选区改为与简历管理一致的 Ant Design `Card`、`Form layout="inline"` 和带标签的 `Form.Item` 布局。筛选项从左到右为：

1. 岗位名称：文本输入，按名称模糊匹配。
2. 部门：单选下拉框，按部门精确匹配。
3. 招聘负责人：单选、可搜索、可清空的下拉框，按负责人 ID 精确匹配。
4. 紧急度：单选下拉框，选项为低、中、高、紧急。
5. 状态：单选下拉框，选项为待发布、招聘中、已关闭。
6. 重置：清空以上五项。

任一筛选值变化后立即重新请求岗位列表。岗位名称输入沿用现有即时请求行为，不额外增加防抖。批量操作控件继续位于筛选卡片内，并在选中岗位时展示。

部门选项来自独立的岗位部门接口，仅返回现有岗位中非空、去重后的部门名称，并按名称排序。招聘负责人选项继续使用现有 `/positions/hiring-managers` 接口。

后端 `GET /positions` 新增可选查询参数：

- `department: str | None`，精确匹配部门。
- `urgency: PositionUrgency | None`，精确匹配紧急度。

新增条件与现有 `title`、`status`、`hiring_manager_id` 条件叠加。所有条件缺省时返回全部岗位。

## 岗位列表字段

岗位列表删除“职位类型”，列从左到右固定为：

1. 岗位名称
2. 部门
3. 招聘人数
4. 招聘负责人
5. 紧急度
6. 状态
7. 招聘进度
8. 创建时间
9. 操作

招聘人数使用 `headcount`，显示为“X 人”；招聘负责人使用列表响应中的 `hiring_manager_name`，未指定时显示 `-`。紧急度、状态和招聘进度继续沿用现有标签、统计与提示样式。

部门、招聘负责人、紧急度和状态的“可筛选”统一通过列表上方筛选卡片实现，不使用表格标题内置筛选菜单。

## 简历管理筛选

简历筛选区继续使用 `Card` 和横向表单，并与岗位筛选的间距、标签、控件尺寸和重置按钮样式保持一致。筛选项从左到右为：

1. 候选人：文本输入，按姓名模糊匹配。
2. 应聘岗位：单选、可搜索、可清空的下拉框，复用页面已经加载的岗位列表。
3. 状态：单选下拉框，沿用现有简历状态选项。
4. 重置：清空以上三项。

移除现有“搜索”按钮。候选人、应聘岗位或状态变化后立即请求简历列表；重置后立即恢复全部可见简历。

前端将应聘岗位 ID 作为 `position_id` 传给现有 `GET /resumes` 接口。该接口和服务已经支持 `position_id` 精确筛选，因此不需要新增后端简历接口能力。

简历解析状态轮询、手动刷新和数据变更后的刷新必须读取调用时的最新筛选条件，不能恢复未筛选数据。面试官请求仍附带当前用户的 `reviewer_id`，保持只查看分配给自己的简历；现有筛选区可见性规则不变。

## 状态与请求一致性

两个页面均使用受控筛选值。重置操作先清空所有筛选状态，再通过统一的列表刷新路径读取最新条件，避免使用旧闭包参数。

岗位页面继续沿用现有“只允许最新请求更新页面”的协调机制，并将新增部门、紧急度加入当前筛选快照。简历页面也需要防止即时输入、轮询和手动刷新之间的旧响应覆盖新筛选结果：所有列表刷新读取当前筛选快照，只有最新请求可以更新列表；只有最新的非静默请求控制 loading 和错误提示。静默轮询仍遵守当前筛选条件。

筛选选项接口加载失败时，列表和其他筛选仍可使用，并显示或记录与现有页面一致的错误信息。

## 测试与验收

后端自动化测试覆盖：

- 岗位按部门精确筛选。
- 岗位按紧急度精确筛选。
- 部门、紧急度、负责人、状态和名称可组合筛选。
- 部门选项去重、排除空值并按名称排序。
- 未登录用户不能读取部门选项。
- 简历现有 `position_id` 筛选保持可用。

前端自动化测试覆盖：

- 岗位查询参数包含部门和紧急度，空值时省略。
- 岗位重置后五项筛选全部为空。
- 简历查询参数包含候选人、应聘岗位、状态及面试官约束。
- 简历重置后候选人、应聘岗位和状态全部为空。
- 即时筛选、轮询和 mutation 后刷新读取最新筛选条件，旧响应不能覆盖新结果。

生产构建和改动文件 ESLint 必须通过。浏览器验收覆盖两个页面的统一样式、即时筛选、重置恢复、岗位列顺序、简历应聘岗位筛选，以及组合条件结果。

## 非目标

- 不增加搜索按钮。
- 不增加表格标题内置筛选菜单。
- 不改变岗位或简历的权限模型。
- 不改变简历状态定义、轮询周期或分页方式。
- 不新增数据库字段或迁移。
- 不在本次工作中处理现有依赖告警、弃用告警或前端包体积提示。
