# 招聘过程质量：流程完整率

入口为侧边栏「招聘过程质量」（`/recruitment-quality`）。仅展示流程完整率，按 HR、简历、适用业务阶段查看记录与推进依据。笔试不在此流程中；岗位资料、简历字段规范和每位面试官的评分不参与此指标，也不因启用本模块增加业务流转拦截。

## 候选人流程卡片

下方明细按候选人记录 ID 汇总，每人一张卡片，上方显示姓名、岗位、跟进 HR 和当前进度，下方以横向点线展示初筛、适用的部门评审、各轮面试、Offer、入职。按时完成为绿色、进行中为蓝色、逾期未完成为红色、逾期后完成为橙色；已暂停和缺少时间记录分别有暂停与问号标识。未开始的节点为空心灰点及虚线，合理终止后不再展示后续未到达步骤。筛选项、图例和节点详情使用相同状态名称，下拉选项附简短说明，悬停图例或节点可查看含义。「有逾期记录」包含尚未完成和逾期后完成的事项；「无需处理」表示当前流程不要求处理这项事项。

节点可以打开原有依据抽屉，查看该阶段与附属异常处理记录。已安排但未产生质量结果的面试也展示实际轮次及预约时间。每位候选人仅展示当前岗位的当前招聘轮次，转岗、恢复后重新招聘的旧流程不再展示；同名不同候选人记录不合并。

「进入业务页面处理」在新标签页打开对应业务入口。按节点仍未完成的要求选择办理页面，已完成或历史节点定位原业务记录。

| 节点／待办 | 办理入口 |
| --- | --- |
| 初筛结论 | 简历详情的 HR 决策表单；AI 建议淘汰等特殊状态保留原业务操作 |
| 指派部门评审 | 简历详情的指派部门评审人表单 |
| 部门评审跟进、HR 决策 | 简历详情的部门评审区域／HR 决策表单 |
| 安排首轮／下一轮面试、取消后重新安排 | 面试管理，预选候选人打开安排面试 |
| 已安排／进行中的面试 | 对应面试 `/interviews/:id/score` |
| 面试反馈、最终决策 | 对应面试 `/interviews/:id/result` |
| 改期或未举行处理 | 面试管理，定位对应面试并打开编辑安排 |
| 面试通过后首次发送 Offer | 已有 Offer 的发送确认；尚无 Offer 时预选候选人打开新建 Offer |
| Offer 答复、重发、到期、撤回处理 | Offer 管理，定位具体 Offer；重新发送进入发送确认 |
| 入职结果登记 | 对应 Offer 的确认实际入职表单；已登记或不可操作时查看原 Offer |

定位使用候选人、岗位、面试和 Offer 的记录 ID。打开链接不自动提交业务操作；页面按当前权限和业务状态决定可用操作。历史流程不自动弹出当前流程的推进表单，转岗后失效的办理链接提示核对岗位。

阶段筛选以真实当前阶段为准；问题条件命中任一节点后保留该候选人的完整流程并突出命中节点。分页以候选人数计算，支持每页 10／20／50／100 人。此汇总只改变展示，完整率仍按下面的阶段与时效规则计算。

## 计算

业务状态与时效判定分别展示。初筛结论、部门评审完成标记及推荐结果、面试最终结果、Offer 实际答复、实际入职记录决定业务是否完成；缺少操作时间不再显示为业务仍在进行。多人部门评审必须全部提交才显示已完成，推荐结果不等于 HR 已通过；部门意见已交齐但未作 HR 决策时显示待 HR 决策。候选人已淘汰、拒绝 Offer 或流程结束后，未完成事项停止等待，已完成的部门推荐等结果继续保留。Offer 到期不等于候选人已答复，撤回和取消也不再提示继续等待原事项。

业务记录能证明已经完成、但没有可核实的完成时间时，显示「已完成」及实际业务结果，时效标为「缺少时间记录」，不推测按时或逾期，不补写历史日期。可核实的历史逾期继续保留。人员总览同时展示业务已完成、待处理和已终止项数，避免把「暂无可统计项」误解为没有候选人或业务没有完成。

人员总览右侧支持按「流程开始日期」选择起止日期，提供今天、近 7 天、近 30 天和本月快捷范围；清空后查看全部时间内的当前招聘轮次。按北京时间计算，包含起止日全天。顶部完整率、人员统计及候选人明细使用同一范围；筛选保留命中流程的全部阶段证据。转岗、恢复后的新流程按各自开始日期筛选，统计显示截至当前的办理结果。

流程完整率 = 按时满足结果登记和后续推进要求的阶段数 / 应考核的阶段数，保留一位小数，分母为零显示「暂无可统计项」。

同一简历的初筛、部门评审、每轮面试、Offer 和入职各按适用阶段汇总，异常事项按对应节点核算。一个节点可含多个要求，但不因字段数、评审人数增加权重。节点仍有未到期事项时暂不计分；一旦任一要求逾期，该节点纳入分母且不得分。补录、补发、更正或补充处理记录均不清除业务操作已经发生的逾期。最终判定按首次有效业务操作证据，不按当前字段是否非空判定。

等待部门评审、面试反馈或 Offer 答复只展示业务进展，不要求周期性登记催办，不设置催办逾期，也不单独增加完整率分子或分母。旧版 `follow_up_days` 配置读取时忽略，原来的催办逾期不再纳入计算；业务办理逾期仍保留。所有说明记录（包括旧版 `follow_up`、`resolve`、`waive`）均仅留痕，不作为完成、改期或延期依据。

初筛合理淘汰、候选人退出等有效终止不要求后续推进。终止前已经发生的逾期保留。历史流程不统一重置起点：有可核实记录的据实计算；缺少必要时间证据的阶段显示「缺少时间记录」，不推测逾期，也不增加分子。迁移推算的面试时间不作为真实操作证据。

## 默认期限

所有期限可由管理员在既有「流程规则」入口配置，全局默认可被岗位规则覆盖。

| 要求 | 默认工作日数 |
| --- | --- |
| 接手后提交初筛结论 | 2 |
| 初筛通过后指派部门评审 | 2 |
| 部门意见全部交齐后提交 HR 决策 | 1 |
| 初筛免评审通过、部门 HR 决策通过后安排首轮面试 | 2 |
| 决定下一轮后安排下一轮面试 | 2 |
| 收齐面试反馈后提交该轮最终决策 | 1 |
| 最终面试通过后首次实际发送 Offer、Offer 重开后发送 | 2 |
| 入职结果登记 | 1 |
| 面试取消后重新安排面试 | 2（使用安排面试期限） |
| 预约结束后更新面试进展、Offer 到期处理 | 1 |

部门评审意见交齐并不等于通过，先进入待 HR 决策；通过后再计安排面试期限。面试安排以时间、面试官、地点／链接齐全并保存为准，不以实际举行或邮件送达为准。面试取消后的处理以实际重新安排、合理终止或备选暂停为依据；预约结束后的进展以实际结束、反馈、决策或有效改期为依据。改期审计保存原预约结束时间，后续改期不清除此前业务逾期。

Offer 草稿不代表发送。候选人的答复和到岗按 Offer 答复期限、约定入职日期等待，不要求两天内实际到岗。Offer 到期后按实际重开、撤回、接受、拒绝或调整答复期限判定处理；已撤回或拒绝本身就是业务结果，不要求再补一条异常说明。入职结果以实际入职确认、调整约定入职日期或变更 Offer 状态为依据；逾期后操作仍保留逾期。

使用北京时间，顺延至第 N 个工作日的同一时刻。中国大陆工作日历包含法定假日和调休补班。依赖 `chinesecalendar==1.11.0`，目前覆盖 2004—2026 年；超出日历覆盖的期限显示证据不足，不静默退化成普通周一至周五。后续年度安排发布后需更新该依赖。

## 备选、重启与归属

列为备选自动暂停尚未完成的流程，不提供独立暂停按钮。备选用于确实暂缓推进的候选人，不用于代替正常等待反馈。离开备选后重新获得完整期限，并采用恢复时适用的规则；暂停前已有逾期不清除。AI 自动标记备选不能作为 HR 人工初筛完成证据。

淘汰后恢复、转岗及返回原岗位按新的流程轮次处理；旧记录保留。每轮面试独立计算。面试结论更正可取消尚未到期的旧分支，但不能删除旧分支已经发生的逾期。

简历跟随岗位 HR。底层审计保留完成或逾期时的负责人和实际操作人；页面按当前名下候选人的当前流程汇总全部阶段，完整率不再按历史负责人过滤。岗位交接不修改已有业务时间、截止时间和已发生的逾期。

人员总览、负责人筛选和阶段依据中的跟进负责人统一使用当前岗位负责人。原负责人不再因历史节点出现在人员总览，HR 也不再查看已交接出去的流程。当前负责人可以查看其名下候选人的全部当前阶段和实际结果，审计记录继续保存在数据库中。流程日期筛选仅作用于当前轮次，候选人转岗后不再展示原岗位流程。

规则发布新版本后，尚未触发的要求使用新配置；已开始的要求按触发时版本计算，不修改原截止时间。规则及操作审计只追加，不覆盖。

## 时间证据

确认入职人数达到本轮岗位 Headcount 时，系统自动将岗位设为已关闭，并在岗位状态历史记录自动关闭原因，关闭时间采用实际登记时间。重复提交同一 Offer 的入职确认不会重复占用 HC。

管理员重开已关闭／已取消岗位（包括批量操作），或恢复已删除岗位时，选择重开方式。默认「纠正误操作」继续原轮次，保留原 HC、候选人和招聘计时；绩效回放忽略被纠正的关闭／取消操作，审计记录保留。选择「新增招聘需求」才创建新轮次和全新 HC，新一轮招聘耗时和任务积分从重开时间起计算，历史候选人及已占用 HC 不自动计入新轮次。

正式上线时，所有历史重开统一延续原轮次，不追溯生成第二轮，包括早期试运行记录。只有上线后明确选择「新增招聘需求」、同时写入 `reopen_mode=new_cycle` 和 `recruitment_cycle_policy_version=1` 的重开才增加轮次。禁止为历史重开批量回填该标记；`previous_recruitment_config` 或单独的 `reopen_mode` 不是新轮次依据。原有季度结算快照不变；历史员工离职释放 HC 不会增加新轮次的名额。

- 初筛：人工状态变更及操作记录。
- 部门评审：各评审提交时间、HR 决策状态操作时间。
- 面试：有效安排保存时间、实际结束与反馈提交时间、最终决策历史；不分别考核每位面试官。
- Offer：最早发送事件、首次接受／拒绝审计；重发和更正保留历史。公开回复与 ORM 入口均记录操作证据。
- 入职：`actual_onboarded_at` 为实际业务日期，新增 `onboarding_recorded_at` 为真正登记时间，两者分开。

节点详情仅保留一个「补充处理记录」按钮，用于记录进展、沟通情况、异常原因及处理结果。当前岗位招聘负责人和管理员可填写，已暂停或已完成节点也可追加说明。内容必填，保存操作人和实际提交时间；记录不改变业务状态、办理期限、质量检查结果或完整率。历史记录保留原类型并标明「历史」。阶段结果、改期、Offer 变更和实际入职仍通过原业务页面提交。接口仅接受 `kind=note`，旧版操作类型不再允许新增；无需修改已有审计数据。
