# 平台管理员控制台设计

## 1. 目标

在现有 AI 面试系统前端中增加一套独立的平台管理员控制台，使平台管理员能够通过页面管理公司（租户）生命周期，不再依赖手工调用 API。

本次实现不改变租户数据模型和平台管理 API，只为已经存在的 `/api/platform/*` 接口提供前端界面。平台控制台与公司业务后台保持严格的身份、令牌和路由隔离。

## 2. 范围

平台控制台提供以下能力：

- 平台管理员登录。
- 查看全部公司及其状态、公司代码、主域名和创建时间。
- 新建公司，同时创建该公司的初始管理员。
- 查看公司详情和全部绑定域名。
- 启用或停用公司。
- 新增域名、修改域名、设置主域名和删除非主域名。
- 平台会话失效时清理平台令牌并返回平台登录页。

本次不实现以下能力：

- 平台管理员自助注册、找回密码或管理其他平台管理员。
- 删除公司及其业务数据。
- 自动修改企业 DNS、客户端 Hosts 或 Caddy 配置。
- 套餐、计费、配额和用量统计。
- 公司管理员在业务后台创建其他公司。

## 3. 方案选择

采用“同一前端工程、独立平台路由和独立平台会话”方案。

平台页面编译进现有前端镜像，使用 `/platform/login` 和 `/platform/tenants` 两个入口。平台 API 客户端只读取 `platform_token`，普通业务 API 客户端继续只读取 `token`。两个拦截器、登录状态和退出逻辑互不复用，避免平台 JWT 被发送给租户业务接口，也避免公司 JWT 被发送给平台控制接口。

不采用复用公司后台身份和布局的方案，因为平台管理员不属于任何租户；也不单独创建第二个前端工程，因为当前平台功能规模不足以抵消独立构建和部署成本。

## 4. 页面与交互

### 4.1 平台登录页

路径为 `/platform/login`。

页面使用独立的“平台管理中心”标识，输入平台管理员邮箱和密码。登录成功后保存 `platform_token` 并跳转到 `/platform/tenants`。登录失败统一显示“登录失败，请检查邮箱和密码”，不暴露账号是否存在。

该页面不显示公司选择器，也不链接到公司业务管理页面。平台管理员不存在时仍需通过 `scripts/create_platform_admin.py` 初始化，页面不提供注册入口。

### 4.2 公司管理页

路径为 `/platform/tenants`，只有存在有效平台令牌时可访问。

页面采用平台专用顶部栏和内容区，显示公司总数、启用数量和停用数量。主体使用表格展示：

- 公司名称。
- 公司代码。
- 主域名。
- 状态。
- 创建时间。
- 查看详情和启用/停用操作。

顶部提供“新建公司”按钮。新建表单包含公司代码、公司名称、主域名、初始管理员邮箱和初始管理员密码。密码至少 12 位，必须同时包含字母和数字。提交成功后关闭表单、刷新列表并显示成功消息；公司代码或域名冲突时显示明确的中文冲突提示。

### 4.3 公司详情与域名管理

点击“详情”后打开抽屉，加载 `/api/platform/tenants/{tenant_id}`，展示公司基础信息和域名列表。

域名管理支持：

- 新增域名并选择是否设为主域名。
- 修改域名文本。
- 将已有域名设为主域名。
- 删除非主域名。

主域名不能直接删除。界面在删除前二次确认，并提示域名变更只修改系统映射，管理员仍需另行维护 DNS、Hosts 和 Caddy。

### 4.4 公司状态

启用和停用通过 `/api/platform/tenants/{tenant_id}/status` 完成。停用操作必须二次确认，并说明停用后该公司的用户不能继续登录和访问业务接口。状态修改成功后同时刷新列表和当前详情。

## 5. 前端结构

新增独立的平台模块：

- `types/platform.ts`：平台公司、域名、登录和新建公司类型。
- `utils/platformRequest.ts`：只处理 `platform_token` 的 Axios 客户端。
- `contexts/PlatformAuthContext.tsx`：平台登录状态、登录和退出。
- `components/Platform/PlatformProtectedRoute.tsx`：平台路由保护。
- `components/Platform/PlatformLayout.tsx`：平台专用布局。
- `pages/Platform/Login.tsx`：平台登录页。
- `pages/Platform/Tenants.tsx`：公司列表和新建公司入口。
- `pages/Platform/TenantDetailDrawer.tsx`：公司详情和域名维护。

现有 `router/index.tsx` 只增加平台路由。现有 `AuthContext`、`request.ts`、公司后台菜单和业务页面不承担平台职责。

## 6. 数据流与安全

平台登录请求不会附带任何现有 token。登录成功后仅把返回的 JWT 写入 `localStorage.platform_token`。

平台 API 请求只附带 `Authorization: Bearer <platform_token>`。收到 401 或平台令牌对应的 403 时，客户端删除 `platform_token` 并跳转 `/platform/login`。普通业务 API 的 401 仍只清理 `localStorage.token`，两种会话互不影响。

所有公司创建、状态修改和域名维护继续由现有后端接口执行，因此保留事务、平台身份校验和 `platform_audit_logs` 审计。前端不直接访问数据库，也不绕过后端约束。

## 7. 错误处理

- 网络失败：保留当前页面数据，显示可重试的中文提示。
- 登录失败：统一提示邮箱或密码错误。
- 令牌失效：清理平台令牌并返回平台登录页。
- 公司代码或域名冲突：保留表单输入，显示冲突提示。
- 表单校验失败：在对应字段下显示中文规则说明。
- 域名删除或状态变更失败：关闭加载状态，保留原数据并显示服务端安全错误信息或通用失败信息。

## 8. 测试与验收

使用 Vitest 和 Testing Library 按测试先行方式覆盖：

- 平台 API 客户端不会发送普通业务 token。
- 普通 API 客户端不会发送平台 token。
- 平台 401 只清理平台令牌并跳转平台登录页。
- 未登录访问 `/platform/tenants` 会跳转 `/platform/login`。
- 平台登录成功后保存令牌并跳转公司列表。
- 公司列表正确展示状态和主域名。
- 新建公司提交完整字段并刷新列表。
- 停用公司和删除域名需要二次确认。
- 主域名不显示直接删除操作。
- 域名新增、修改和设为主域名调用正确接口。

最终验收还包括完整前端测试、TypeScript 构建、Docker 前端重建，以及通过本地 HTTPS 实际验证平台登录入口和现有公司登录入口互不影响。

## 9. 运维边界

页面创建公司后，数据库中的租户、主域名映射、初始管理员和系统配置立即生效。若使用新的专属域名，运维人员还必须把域名解析到服务器，并确保 Caddy 的站点域名配置包含该域名；页面会明确提示，但不自动修改基础设施。
